# Turning Data Heterogeneity into a Backdoor Shield for Personalized Federated Learning (CCS)

**会议/年份**: ICASSP 2026
**作者单位**: Nanjing University of Information Science and Technology, Engineering Research Center of Digital Forensics (Ministry of Education)
**论文类型**: 防御方法（针对PFL的后门防御，Client-Centric Shielding）

---

## 1. 核心问题与动机

- PFL的个性化虽然缓解了数据异构性问题，但也带来了新的安全隐患：**模型多样性增大、共享知识减少，削弱了传统全局防御的有效性**。
- 传统FL鲁棒聚合方法（Multi-Krum, FLAME）在PFL场景下效果显著下降：客户端间参数分歧过大，违反了"良性更新紧密聚簇"的核心假设，导致无法区分恶意偏差与non-IID导致的正常差异。
- **关键批判**：现有PFL原生防御方法（ST, FLIGHT, SARS, PFL-ALB等）的鲁棒性建立在一个**错误假设**上——即客户端在本地数据上微调会自然清除从全局模型继承的恶意更新。但PFL专用后门攻击（PFedBA, Bad-PFL, BapFL等）恰恰是**利用个性化过程本身作为攻击载体**，专门设计成能在个性化阶段存活：
  - **PFedBA** [6]：交替优化触发器和模型参数以最小化投毒输入的分类损失，同时通过最小化欧氏距离对齐主任务和后门任务梯度，使投毒模型的决策边界模仿良性模型，从而绕过服务器检测并在个性化阶段持续存在
  - **Bad-PFL**：用自然数据特征作为触发器实现隐蔽性（见前述文档）
  - **BapFL**：见前述文档
- **本文核心洞察**：直接将中心化学习中的特征空间对抗训练（purifying backdoored features）搬到PFL不可行，因为：
  1. non-IID特性导致缺乏目标类别数据的客户端无法有效净化
  2. 客户端间模型分歧巨大，任何统一施加的扰动都无效
- **核心创新**：**把数据异构性从"问题"转变为"防御资产"**——不抵消异构性，而是利用它，让每个客户端独立生成本地对抗样本，主动重塑自己模型的决策边界，扩大本地数据特征表示周围的margin。

## 2. 背景：PFL两种范式（公式回顾）

**Full Model-Sharing**（如Ditto, pFedMe）：
```
min_{Θg,{Θi}} (1/N) Σ_i E_(x,y)~Di[L(f(Θi;x),y)] + λH(Θg,Θi)
```
λ控制局部损失与全局正则化项的权衡。

**Partial Model-Sharing**（如FedPer）：模型分为全局特征编码器θg + 个性化分类器hi，仅θg参与聚合：
```
min_{θg,{hi}} (1/N) Σ_i E_(x,y)~Di[L(f(θg,hi;x),y)]
```

---

## 3. 威胁模型

### 3.1 攻击者
- **对被攻陷客户端**：完全白盒控制，可无限制访问其本地数据集和个性化过程
- **对良性客户端和中心服务器**：仅黑盒访问
- **对防御机制**：不知晓CCS在客户端或服务器端部署的任何防御
- 后门目标：使任何嵌入触发器Δ的输入被一致误分类为目标标签yt

恶意客户端优化目标（公式3）：
```
min_{θg,{hi}} (1/N) Σ_i [ E_(x,y)~Di[L(f(θg,hi;x),y)]
                          + λ E_(x,y)~Dmal[L(f(θg,hi;x+Δ), yt)] ]
```

### 3.2 防御者
- 良性客户端被动，严格遵守CCS协议，不部署额外防御
- 中心服务器同样受限：既不能识别恶意客户端身份，也不能检查其本地训练过程（黑盒约束）
- 目标：从根本上破坏后门植入过程，在保持模型效用的同时降低攻击有效性

---

## 4. 核心方法：Client-Centric Shielding (CCS)

CCS由两个协同组件构成：**客户端侧个性化对抗训练** + **服务器侧基于BN统计量的聚类防御**

### 4.1 客户端本地训练（Local Client Training）

**步骤1：生成对抗样本**
- 先用 **Deformable Patch Representation** [25] 在增强后的干净样本上初始化基于patch的扰动
- 再通过优化 max-margin 损失来精细化对抗样本：
```
x_i^adv = argmin_{xi,yi}∈Di [ L(xi;yi) - max_{y'i≠yi} L(x_i^adv; yi) ]
```

**步骤2：输出一致性（KL散度损失）**
```
L_KL = E_(x,y)~Di [ D_KL( f(θi,pi,hi;x) || f(θi,pi,hi;x^adv) ) ]
```
其中 f(θi,pi,hi;·) 表示引入了**个性化投影网络pi**的模型输出。

**步骤3：特征表示对齐（MMD损失）**
```
L_MMD = || E_(x,y)~Di[ φ(θi,pi;x) - φ(θi,pi;x^adv) ] ||²_H
```
（Maximum Mean Discrepancy，最小化干净样本和对抗样本经投影网络后的特征分布差异）

**最终本地训练目标（复合损失）**：
```
L = L_CE + β · L_KL + γ · L_MMD
```
- L_CE：标准交叉熵损失（保证任务准确率）
- β, γ：鲁棒性项权重超参数

**核心机制解释**：优化该复合目标促使个性化模型学习一个与本地数据流形更紧密对齐的决策边界，使其偏离（脆弱的）被投毒全局模型的边界。这种"偏离"正是CCS防御的核心——后门触发器之所以失效，是因为它的成功依赖于利用全局模型决策边界的特定漏洞，而现在这个边界已被personalized对抗训练改变。

### 4.2 服务器端模型聚合（Model Aggregation on Server）

- 每个客户端训练完成后，仅上传**特征编码器**给中心服务器
- **核心检测机制**：服务器使用 **HDBSCAN 聚类算法**，对每个客户端构造的向量 v_c 进行聚类
  - v_c 由客户端上传编码器中 **BN层的 running_mean 和 running_variance 统计量**构成
  - **关键优势**：这些统计量直接从数据批次(batch)计算得到，与基于梯度的权重优化过程**隔离（insulated）**——攻击者无法通过操纵梯度来掩盖恶意的统计偏差，从而规避常规的（基于权重/梯度的）服务器端检测
  - 这是**首个利用此类向量进行PFL安全检测的框架**（论文声称的创新点之一）
- 识别并排除恶意客户端后，服务器用标准 **FedAvg** 聚合剩余良性客户端模型：
```
θ_g^{t+1} = Σ_{n=1}^N (1/N) θ_i^t
```

### 4.3 框架示意（Fig.1）
Client侧：Feature Encoder → Projection Network → Local Classifier，同时处理Clean Samples和Adversarial Examples，产生L_CE + L_KL和L_MMD损失（前向/反向传播）
Server侧：收集各客户端向量v1...vn，做Model Aggregation（聚类排除恶意后FedAvg）

## 5. 实验设置

### 5.1 数据集与模型
| 数据集 | 模型 | 训练轮数 |
|---|---|---|
| MNIST | ConvNet | 200 epochs |
| SVHN | ResNet-18 | 500 epochs |
| CIFAR10 | ResNet-18 | 1,000 epochs |

### 5.2 FL/PFL设置
| 参数 | 取值 |
|---|---|
| 客户端总数 | 100 |
| 恶意客户端比例 | 10% |
| Non-IID划分 | Dirichlet分布，α = 0.5（与PFedBA一致的方法学） |
| 每轮参与比例 | 10%随机采样 |
| 本地训练步数 | 2 steps/round |
| 本地优化器 | SGD |
| 本地学习率 | 0.1 |
| batch size | 64 |
| CCS关键超参数 β, γ | 均为 0.01 |
| 默认PFL框架 | FedPer |
| 默认攻击 | Blended attack（除非特别说明） |

### 5.3 Baseline对比
**攻击方法（两类）**：
1. 传统FL后门攻击：FCBA [22], LPA [21]
2. PFL专用攻击：BapFL [24], PFedBA [6], BADPFL（即Bad-PFL）[5]

**防御方法（两类）**：
1. 传统FL防御：Multi-Krum [7], FLAME [8]
2. PFL个性化防御：ST [4], FLIGHT [10], SARS [11], PFL-ALB [12]

### 5.4 评价指标
- **MTA**（Main Task Accuracy）：良性客户端在干净测试数据上的平均准确率
- **ASR**（Attack Success Rate）：含后门触发器的测试数据上的平均（误分类为目标类）准确率

**关键结论**：
- 面对最强的PFedBA攻击，多数已有防御方法的ASR仍超过80-90%（例如 SARS在CIFAR10上达87.59%），而 **CCS将ASR降至个位数（如CIFAR10上8.56%）**，同时保持高MTA
- CCS并非在每个单独场景下都绝对最优（个别数值略低于其他方法），但在**攻防平衡（robustness vs utility trade-off）上取得整体最优**，对多种攻击都能提供一致的防护，这是相比现有SOTA的显著进步

### 6.2 不同数据异构程度下的鲁棒性（Fig.2，CIFAR10，Dirichlet α ∈ {0.1, 0.3, 0.5, 1}）
- CCS在所有测试的α值下均保持稳定防御性能
- **α=1**（更接近IID）时：CCS针对BADPFL攻击仍能将ASR降至约10%；相比之下裸FedPer的ASR接近100%
- 这一鲁棒防御的实现**几乎不损失模型效用（MTA）**

## 7. 面向 Claude Code 复现的关键要点摘要

1. **两大核心模块需分别实现**：
   - **客户端侧**：个性化投影网络 p_i + 对抗样本生成（Deformable Patch Representation + max-margin优化）+ 复合损失（CE + β·KL + γ·MMD）
   - **服务器侧**：从每个客户端上传的encoder中提取BN层的 running_mean 和 running_variance 构成向量v_c，用 **HDBSCAN** 聚类，排除异常簇（恶意客户端），再对剩余客户端做标准FedAvg
2. **关键实现细节**：
   - 对抗样本生成分两步：先用Deformable Patch做patch-based扰动初始化，再优化max-margin loss进一步精细化（注意这是攻击性对抗样本生成技术，非随机噪声）
   - BN统计量检测的核心优势在于其**计算独立于反向传播梯度**，这意味着即使攻击者操纵梯度更新（如通过梯度裁剪、投影等规避检测手段），BN running统计量仍会暴露异常数据分布特征——实现时注意提取的是每个客户端上传encoder中所有BN层的running_mean/running_var（不是权重本身）
3. **需要实现的对比攻击**（用于测试防御强度）：至少需要 PFedBA（当前最强攻击，多数防御对其ASR都超80%）、Bad-PFL（BADPFL）、BapFL；这三者与前面已整理的文档形成呼应，可以复用之前提取的攻击实现细节
4. **需要实现的对比防御**：Multi-Krum, FLAME（传统鲁棒聚合），以及PFL专用防御 ST（仅重训练个性化分类器）、FLIGHT、SARS、PFL-ALB（两阶段：层级梯度相似度矩阵+自适应划分global/personalized层）
5. **关键超参数速查**：100 clients，10%恶意，Dirichlet α=0.5（默认，也可扫0.1/0.3/0.5/1），本地SGD lr=0.1, batch=64，本地步数=2/round，默认PFL框架FedPer，CCS的β=γ=0.01
6. **默认攻击设置**：标准评估协议采用 FedPer 中的 **Blended attack**（除非特别说明使用其他攻击）
7. 未来工作方向（论文提及）：将当前"二元排除"式防御（识别到恶意就完全剔除）泛化为**自适应聚合方案**——根据个性化模型与全局模型的divergence，给异常客户端赋予衰减权重而非直接剔除（可作为进一步改进/复现的扩展点）
