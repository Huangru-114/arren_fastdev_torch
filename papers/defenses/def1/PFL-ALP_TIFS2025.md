# PFL-ALP: Personalized Federated Learning Against Backdoor Attacks via Attention-Based Local Purification

**期刊/年份**: IEEE Transactions on Information Forensics and Security (TIFS), Vol.20, 2025 (published Dec 2025)
**作者单位**: Macao Polytechnic University, Guangdong University of Technology
**论文类型**: 防御方法（服务器动态聚类 + 客户端注意力蒸馏净化的混合防御）

---

## 1. 核心问题与动机

现有防御方法分为两类，各有局限：

### Server-side防御的局限
- 基于统计的方法（median, trimmed mean, geometric median等）在面对**控制大量客户端的激进攻击者**时失效，检测机制容易被恶意更新淹没
- 攻击者可制造与良性更新高度相似的投毒更新，使统计区分失效
- 基于裁剪（clipping）的方法对**小幅度**恶意更新无效（幅度仍在裁剪阈值内）
- 统计类和裁剪类方法都需要**明文模型更新**，易受服务器端推断攻击（inference attack）影响
- 部分方法（FLTrust, 多教师蒸馏）需要服务器持有**干净的辅助数据**，现实中难以获取

### Client-side防御的局限
- 基于扰动的方法（FL-WBC）通常是**无差别性**的（untargeted），可能引入额外偏差并损害模型性能
- 基于注意力的方法（Fed-NAD, SPFL）是**有针对性**的，利用"后门劫持模型对触发器的注意力"这一观察，试图将注意力与良性参考对齐；但这类方法**严重依赖本地历史模型的知识**，在Non-IID场景下泛化性差，效果显著下降

### 核心洞察：动态聚类的价值被重新定位
论文用DBA攻击在MNIST的Non-IID场景做了一个关键实验（Fig.2）：10个客户端（3恶意）参与训练，对其模型更新做PCA降维+聚类可视化。**结果显示：动态聚类能将数据分布相似的客户端聚为一类，但无法把恶意更新过滤出去**（恶意更新会跟良性更新混在同一簇里）。
→ 这意味着聚类**不该被用作"识别恶意客户端"的手段**（这是先前工作FLAME/FLShield的做法），而应该被用作**"缓解Non-IID偏差"的工具**——先把数据分布相似的客户端分为一组，生成组内代表模型，再在客户端侧做净化去除后门信息。

## 2. 核心方法：PFL-ALP（两阶段防御）

### 2.1 FL基本设定（公式回顾）
标准FedAvg：
```
本地更新: θ_{k,e+1}^t = θ_{k,e}^t - η∇ℓ(θ_{k,e}^t)     (Eq.1)
服务器聚合: θ^{t+1} = θ^t - Σ_{k∈St} (|Dk|/Σ|Dk|) ∇ℓ(θ_k^{t+1})   (Eq.2)
```

### 2.2 威胁模型
- 攻击者可控制客户端子集，**恶意比例可能超过50%**
- 攻击者可访问被攵陷客户端的本地模型和数据，可操纵本地训练过程和上传参数
- 攻击者完全了解聚合算法和配置，但无法更改它们
- 攻击者无法控制良性客户端
- 目标：注入后门使模型对特定实例误分类，同时保持主任务正常性能

### 2.3 防御者假设
- 不违反FL隐私原则（不暴露良性客户端原始数据）
- 无额外辅助数据集
- 不知道参与客户端的数据分布
- 不知道任何后门知识（恶意客户端比例、触发器等）
- 服务器是honest-but-curious（对客户端原始数据好奇），防御方法不能违反隐私计算机制

### 2.4 算法总览（Algorithm 1: PFL-ALP Algorithm）
```
输入：全局模型θ, 总轮数T, 本地更新epoch数E, 被选中客户端集合St
输出：每个良性客户端的个性化模型 ξ_k^{t+1}

for 每轮 t ∈ [1,T]:
    # 服务器执行
    将当前全局模型θ^t发给被选中客户端

    # 客户端执行
    for 每个客户端 k ∈ St:
        接收全局模型θ^t
        用本地数据更新θ^t，将梯度∇ℓ(θ_k^{t+1})发回服务器 (Eq.1)

    # 服务器执行
    接收所有被选中客户端的本地更新
    for 每对更新:
        计算距离度量 Md(pair)  (Eq.3)
    (g1,...,gc) ← DynamicClustering(scores矩阵)
    for 每个组 j ∈ [1,c]:
        ωj^{t+1} ← Generate(gj)   # 加权平均聚合 (Eq.5)
    θ^{t+1} ← GlobalUpdate(...)   # 标准全局模型更新 (Eq.2)
    将对应的代表模型ωj^{t+1}发给各客户端

    # 客户端执行
    for 每个客户端 k ∈ St:
        接收代表模型ωk^{t+1}
        if 客户端k是良性:
            ξk^{t+1} ← Purification(ωk^{t+1})   # Algorithm 2
```

**关键点**：全局模型θ只用于下一轮本地训练的warm start和动态聚类的基础，实际用于推理和净化指导的是**净化后的代表模型（个性化模型）**。

### 2.5 阶段一：动态聚类构建代表模型（Dynamic Clustering-Based Representative Model Generation）

**距离度量**：基于成对余弦距离评估模型更新间的角度差异
```
Md = 1 - <u,v>/(||u||·||v||)     (Eq.3)
```
取值范围[0,2]，值越低表示两更新越相似。

**距离矩阵**（Eq.4）：对所有被选中客户端St（|St|=n）两两计算Md，得到n×n矩阵scores。

**聚类算法**：K-MEANS。由于事先不知道确切的簇数量，通过**轮廓系数（silhouette score）**评估确定最优簇数c。

**代表模型生成**（组内加权平均聚合，Eq.5）：
```
ω_gj^{t+1} = θ^t - Σ_{k∈gj} (|Dk| / Σ_{k∈gj}|Dk|) ∇ℓ(θ_k^{t+1})
```

### 2.6 阶段二：基于注意力的本地净化（Attention-Based Local Purification）

**两阶段流程**（Fig.4）：
1. 良性客户端先在本地数据上微调其个性化模型，学习良性、与本地数据一致的知识
2. 将这个（微调后的）个性化模型作为**冻结的教师（frozen teacher）**，将服务器发来的代表模型作为**学生（student）**；在本地数据上训练学生模型，最小化NAD损失+任务损失的联合目标，促使学生的注意力与教师对齐，同时保持任务性能
3. 净化后的代表模型被提升为新的个性化模型，用于本轮推理，并在下一轮作为teacher

**任务损失**（Eq.6）：
```
L_CE,ξk = ℓ_CE(ξk(x), y)
```

**注意力映射函数**（Eq.7）：给定第l层激活输出 A^l ∈ R^{C×H×W}
```
F^p(A^l) = (1/C) Σ_{i=1}^C |A_i^l|^p
```
将p设为2（放大干净模型与后门模型神经元间的差异，参考文献[24] NAD原始论文的建议）

**NAD损失**（Eq.8，衡量学生ω和教师ξ在第l层注意力的差异）：
```
L_NAD(ω_k^l, ξ_k^l) = || F^p(A_ωk^l)/||F^p(A_ωk^l)||_2 - F^p(A_ξk^l)/||F^p(A_ξk^l)||_2 ||
```

**代表模型的主任务损失**（Eq.9）：
```
L_CE,ωk = ℓ_CE(ωk(x), y)
```

**净化的最终复合目标**（Eq.10）：
```
L_ωk = E_(x,y)∈Dk [ L_CE,ωk + β Σ_{l∈L} L_NAD(ωk^l, ξk^l) ]
```
其中L为注意力层数，β为控制知识迁移强度的超参数。

**Algorithm 2: Attention-Based Local Purification**
```
输入：代表模型ωk^{t+1}, 净化轮数R
输出：更新后的个性化模型ξk^{t+1}

for 每个净化轮 r ∈ [1,R]:
    for 每个mini-batch d in Dk:
        更新本地个性化模型ξk^t（在主任务上）  (Eq.6)
        计算NAD损失（ξk^t 与 ωk^{t+1}之间）  (Eq.8)
        计算代表模型ωk^{t+1}的主任务损失  (Eq.9)
        净化代表模型ωk^{t+1}  (Eq.10)
ξk^{t+1} ← ωk^{t+1}
return ξk^{t+1}
```
注意：初始轮次良性客户端还没有个性化模型时，可用其本地模型作为净化指导的替代。

### 2.7 隐私方面（PFL-ALP与STPC结合）
- PFL-ALP兼容 **STPC（Secure Two-Party Computation）**，可引入外部服务器与中心服务器协作进行隐私计算（如ABY框架）
- **关键区别（相比FLAME/FLShield/LSFL/EPPRFL等STPC-based防御）**：先前工作用STPC实现"安全鲁棒聚合"（如安全实现k近邻筛选或欧氏距离裁剪）；本文用STPC是为了在**降低Non-IID偏差**的过程（动态聚类+代表模型/全局模型构建）中保护隐私，而**后门净化步骤本身在本地进行，不需要STPC**（因为它只依赖本地数据和本地个性化模型，天然保护隐私）
- 具体做法（Fig.5）：客户端将模型更新∇ℓ(θk^{t+1})拆成两部分 A、B，分别发给中心服务器和外部服务器；两服务器联合用STPC安全执行动态聚类和代表模型/全局模型生成

### 2.8 收敛性理论保证（Section IV-E）
针对本地净化阶段（教师ξ冻结，学生ω通过最小化复合目标J(ω)=L_ωk优化）建立收敛保证：

**假设**：
1. L-光滑性：∇L_CE,ω是Lt-光滑，∇L_NAD是La-光滑，联合目标J(ω)是 L:=(Lt+βLa)-光滑
2. μ-强凸性：J(ω)在极小值点ω*附近局部μ-强凸
3. 无偏随机梯度：E[gr|ωr]=∇J(ωr)，E||gr-∇J(ωr)||²≤σ²

**定理1（本地净化目标的线性收敛）**：
当 0 < η ≤ 1/L 时：
```
E[J(ωr) - J(ω*)] ≤ (1-μη)^r [J(ω0) - J(ω*)] + (ηL/2μ)σ²
```
（完整证明见论文Lemma 1-3及Theorem 1的推导，基于标准SGD在L-光滑+μ-强凸假设下的经典分析套路）

## 3. 实验设置

### 3.1 数据集与模型
| 数据集 | 模型 |
|---|---|
| MNIST | CNN（同DBA论文[7]架构） |
| Fashion-MNIST | 同上CNN |
| CIFAR-10 | ResNet18（同Bad-PFL论文[5]架构） |

### 3.2 评测的后门攻击（5种）
1. **SA（Semantic Attack）**[5]：三种触发器类型——background wall (wall), racing stripe (stripe), green car (car)
2. **ECBA（Edge-Case Backdoor Attack）**[26]：用Southwest Airlines飞机类图像作为edge-case样本（CIFAR-10），误标为truck
3. **BA（Badnet Attack）**[6]：像素块触发器，三种尺寸：3×3, 5×5, 7×7（CIFAR-10）
4. **DBA**[7]：分布式后门攻击，触发器拆成4部分，三个数据集均测试
5. **TLFA（Targeted Label Flipping Attack）**[43]：类别对——CIFAR10: (automobile,truck)；Fashion-MNIST: (coat,shirt)；MNIST: (digit 5, digit 3)

### 3.3 Baseline防御（6种）
- FedAvg（无防御）
- Server-side：**FLTrust**, **FLAME**, **Multi-metrics**
- Client-side：**FL-WBC**
- Hybrid：**FLShield**

### 3.4 数据划分（one class-expert distribution）
- 客户端随机分为c组（c=数据集类别数=10）
- 标签j的样本以概率p分配给组j，以概率(1-p)/(c-1)分配给其他组
- **IID场景**：p = 0.1
- **Non-IID场景**：p = 0.5（后续鲁棒性分析中p可扫0.1~0.5）

### 3.5 关键超参数
| 参数 | 取值 |
|---|---|
| 客户端总数 K | 100 |
| 恶意客户端比例（默认） | 30% |
| 每轮参与客户端数 | 10（其中3个恶意，默认30%场景下） |
| 总训练轮数 | 100 |
| 良性客户端：本地epoch E | 1 |
| 良性客户端：batch size B | 64 |
| 良性客户端：学习率 η | 0.1 |
| 恶意客户端（攻击时）：本地epoch E | 6 |
| 恶意客户端：batch size B | 64 |
| 恶意客户端：学习率 η | 0.05 |
| 攻击持续性 | 全程持续攻击 |
| PFL-ALP的β（默认最优值） | 1500（消融实验确定，见4.3节） |

### 3.6 评价指标
- **MA**（Main task Accuracy）
- **ASR**（Attack Success Rate）
- **RS**（Ranking Score）：综合多种攻击相对FedAvg的整体提升
  ```
  RS = Σ_攻击 [ (MA_D - MA_B)/MA_B - (ASR_D - ASR_B)/ASR_B ]
  ```
  其中下标D为防御方法，B为FedAvg基线
- 对于基于个性化模型的防御（PFL-ALP, FL-WBC）：MA/ASR取所有良性客户端个性化模型的均值；其他基于单一全局模型的防御则报告最终全局模型的性能

### 3.7 硬件环境
PyTorch 2.4.1，Ubuntu 24.04，RTX GPU 8000e，Intel Xeon Gold 5218 @2.30GHz

## 4. 主要实验结果

### 4.1 CIFAR-10 IID场景对抗SA/BA/ECBA（Table I）
| 防御 | Wall(MA/ASR) | Stripe(MA/ASR) | Car(MA/ASR) | RS |
|---|---|---|---|---|
| FedAvg | 73.61/100 | 70.92/100 | 72.92/100 | 0 |
| FLTrust | 71.90/6.67 | 71.23/20.00 | 66.83/3.33 | 5.66 |
| FLAME | 70.69/16.67 | 73.23/13.33 | 71.41/27.33 | 2.88 |
| **PFL-ALP** | **73.45/0.00** | **73.57/0.00** | **73.30/0.00** | **6.54(最高)** |

### 4.2 CIFAR-10 Non-IID场景对抗SA/BA/ECBA（Table III）
| 防御 | Wall(MA/ASR) | RS |
|---|---|---|
| FedAvg | 62.94/100 | 0 |
| FLTrust | 51.65/0.00 | 4.51 |
| FLAME | 41.80/0.00 | 3.34 |
| **PFL-ALP** | **65.48/0.00** | **6.57（最高）** |

**关键发现**：在Non-IID场景下，FLTrust/FLAME虽然仍能压低ASR，但MA大幅下降（常低于50%）；FL-WBC/FLShield则在BA攻击下ASR超过90%；PFL-ALP保持MA>65%（SA各触发器）、MA>61%（BA各尺寸），ASR保持在0-5%区间。

### 4.3 DBA与TLFA对比（Table II IID, Table IV Non-IID）
- IID场景MNIST任务上，FLAME在DBA上表现最好（MA=96.72%, ASR=0.53%），PFL-ALP次优（MA=95.33%, ASR=3.35%）
- **但Non-IID场景下**，FLAME等方法在该任务上失效（ASR超97%），**PFL-ALP仍保持ASR=6.08%**
- 部分方法（如Multi-metrics）在IID下有效（BA的ASR为32.71%/35.17%），但Non-IID下骤增至67.95%/90.94%
- **不对称的鲁棒性问题**：一些方法（FLTrust, FLAME, FLShield）为了应对Non-IID，采用动态聚类+裁剪/过滤/加噪，但这些手段在IID场景下反而引入副作用（例如FLTrust防御DBA时，Non-IID下ASR=9.09%，IID下反升至39.59%）。PFL-ALP因为净化机制基于个性化模型知识（强调泛化知识而非引入额外噪声），在IID和Non-IID下都保持鲁棒（总RS分别领先第二名FLTrust约1分和2分）

### 4.4 鲁棒性分析

**Non-IID程度扫描**（Fig.6，CIFAR10, ECBA攻击，p∈{0.1,...,0.5}）：
- Server-side方法（FLTrust, FLAME）随p增大MA漂移，ASR出现波动/反转（不稳定）；FLTrust的ASR在p=0.2时约19%，p=0.3时降至约11%，之后又随p增大而回升，MA降至约46%
- Client-side方法（FL-WBC）MA随p增大逐渐降至约45%，ASR不稳定（p=0.3时约55%，p=0.5时约48%）
- **PFL-ALP在所有异构程度下ASR均不超过12%，MA始终最高**

**恶意比例扫描**（Table V，CIFAR-10，恶意比例50%/70%/90%）：
- PFL-ALP因采用客户端侧净化清除后门信息，性能受恶意比例变化影响极小，MA/ASR波动多数低于5%
- 例如对抗SA攻击，90%恶意比例下PFL-ALP的ASR仍保持在0-1%（如Wall: ASR=1.00%(-99), Stripe: ASR=0.00(-100)），MA相对FedAvg仅小幅变化
- 对比：即使在70%恶意比例下，FedAvg的ASR普遍接近90-100%

### 4.5 面对"知晓防御机制"的高级攻击（Table VI）
提出两种针对PFL-ALP设计的自适应DBA变体：
- **SDBA（Saliency-guided Stealth-DBA）**：把触发器放在图像次显著区域，与任务相关特征重叠，试图让净化方法在净化激活时"投鼠忌器"（净化会同时压制真实语义）。结果：SDBA确实导致MA有所下降（相比标准DBA下降约2-3个百分点），但ASR仍从99%+降至个位数（CIFAR10: IID下99.96%→26.66%，Non-IID下99.07%→3.32%；虽然MA略有损失，是净化方法固有的局限）
- **ADBA（gradient-aligned Adaptive-DBA）**：优化后门目标的同时对齐梯度到良性参考，试图绕过余弦相似度筛选。结果：PFL-ALP对此攻击**具有天然抵抗力**，因为PFL-ALP的余弦相似度度量只用于Non-IID偏差缓解（聚类），而非直接用作后门检测依据，因此ADBA针对"绕过余弦相似度检测"设计的策略对PFL-ALP无效（MNIST上ASR从99.75%/99.87%降至5.07%/4.38%）

### 4.6 消融实验

**β超参数影响**（Fig.7，CIFAR10, BA攻击不同触发器尺寸）：
- β增大 → MA和ASR都下降
- **最优β=1500**：能有效降低ASR同时保持较高MA；继续增大β对ASR改善有限，但会持续损害MA

**两组件贡献度**（Fig.8，ECBA攻击）：
- 仅用动态聚类（Fed-Cluster）：MA最高，但ASR因代表模型仍含后门残留而显著偏高
- 仅用本地净化（Fed-LP）：ASR降低，但MA有所损失
- **两者结合（完整PFL-ALP）**：ASR降至接近0，MA仅略低于Fed-Cluster——验证两组件的互补性和整体有效性

### 4.7 注意力图可视化（Fig.9，BA攻击 3×3触发器）
- FedAvg：注意力偏移到触发器所在位置（右下角），导致误分类
- FLShield：注意力与触发器高度对齐，ASR高
- FL-WBC / Multi-metrics：注意力大而弥散，同时覆盖物体和触发器，语义焦点被侵蚀
- FLAME：成功抑制触发器，但注意力常碎片化或偏离主体
- **PFL-ALP 和 FLTrust**：成功抑制触发器，同时注意力保持集中在任务相关物体上，ASR最低、主任务表现最好

## 5. 面向 Claude Code 复现的关键要点摘要

1. **两阶段流水线是复现核心**：
   - **阶段1（服务器）**：收集本轮所有被选中客户端的梯度更新 → 计算成对余弦距离矩阵 → K-MEANS聚类（用silhouette score自动确定簇数c）→ 每簇内加权平均生成代表模型
   - **阶段2（客户端）**：良性客户端收到代表模型后，先微调自己的个性化模型（教师，冻结），再用NAD损失+任务损失联合训练代表模型（学生），净化后的模型成为下一轮的个性化模型/教师
2. **NAD损失实现细节**：注意力映射函数 `F^p(A^l) = (1/C)Σ|A_i^l|^p`，p=2；损失是教师和学生归一化后注意力图的L2距离（Eq.8），需要选取多个中间层（L层）计算并求和
3. **区别于FLAME等方法的关键**：**聚类不用于识别/剔除恶意客户端**，而是单纯用于缓解Non-IID导致的偏差（生成代表模型）；真正的后门清除靠客户端侧的NAD净化
4. **恶意/良性客户端区分**：论文的威胁模型假设防御者不知道哪些客户端是恶意的，因此实际实现中"if client k is benign then purification"这行需要注意——从工程角度，可以理解为**所有客户端**都执行净化步骤（良性客户端的个性化模型自然会因为在良性数据上训练而保持干净，从而使净化有意义；对恶意客户端而言，净化步骤对系统整体鲁棒性没有实质影响，因为其自身不诚实执行协议）
5. **关键超参数速查**：100 clients，恶意比例默认30%（可扫50/70/90%测试鲁棒性），每轮选10个客户端参与，良性E=1/lr=0.1/batch=64，恶意E=6/lr=0.05/batch=64（注意攻击者本地训练轮数更多，这是模拟更强攻击者的设置），总轮数100，PFL-ALP最优β=1500
6. **需要实现的对比攻击**：至少需要 BA（Badnet，最基础）、DBA（分布式触发器）、SA（语义攻击，来自Bad-PFL同作者早期工作）三种；若要测试更强鲁棒性，还需实现文中提出的SDBA和ADBA两种自适应攻击变体
7. **STPC部分是可选的隐私增强层**：如果只关注防御算法本身的有效性（ASR/MA），可以先在明文域实现聚类+净化逻辑，隐私保护（ABY框架/STPC）可作为后续扩展
8. 该论文提供了**严格的收敛性证明**（Theorem 1），如果需要验证复现代码的训练动态是否符合理论预期，可参考公式(23)的线性收敛速率形式：`E[J(ωr)-J(ω*)] ≤ (1-μη)^r · [初始差距] + 常数项`
